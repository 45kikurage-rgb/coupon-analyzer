# coupon-analyzer

独立した「クーポン判定」PWAです。画面とAPIを別リポジトリに分離し、Cloudflare Service Bindingで `coupon-analyzer-api` を利用します。

- 安定解析 / 高速解析
- 最大2,000URL、重複URL除外、100件ずつ分割解析、API側で最大3回の解析試行
- 2,000件超は解析前に通知。通信失敗・応答欠落も判定不能として全件を結果に残し、後続を解析
- 共通APIの1リクエスト上限（500件）・同時実行数・判定契約は変更しません
- セブン・ファミマ・プチギフト（ローソン）の整形済みスクリーンショットとZIP
- 商品名・容量・期限・利用済み・Giftee残高の表示
- SBギフト・スターバックスを含む解析API対応URLを画面から判定
- 手動修正と解除（このサイトだけで操作）

クーポンキャプチャーのサイトやAPIには依存しません。

## 2026-11-08 プチギフトの撮影対応

`coupon.petit.gift/coupons/detail` のローソンクーポンを撮影できます。商品名・店舗利用期限・公式バーコード画像を読み取り、画像に含まれる18桁（先頭0）と券面の17桁が一致する場合だけ画像を生成します。バーコードは店舗名の下に配置し、既存のPNG保存・重複判定・ZIPを使用します。解析だけでなく撮影も対応します。

対応店舗・期限・番号を確認できないページは画像を生成せず、引換・使用操作は行いません。元URLの認証パラメータは画像とエラー応答に載せません。既存のDB・認証・公開URL・サービスバインディングは変更しません。

検証：3リポジトリ合計78テスト成功、2 Workerのdry-runビルド成功。実URLのHTMLで商品名・店舗利用期限・バーコード照合を確認。本番反映と公開後撮影は別途確認します。


## 2026-11-09 SBギフトの撮影対応・一括解析の調整

サーティワンのSBギフト（`/cp/exchange/...`）を両画面の撮影対象に追加。券面の24桁とページ内のバーコード定義が一致する場合だけCode128 Cを生成し、表示番号との一致をデコーダーで検証する。画像には公式の「スクリーンショットでは引換不可」を残す。券面表示は元URLを使用する。クーポンの利用確定操作は行わない。

共通APIではSBギフトの基本解析に不要な商品画像の取得を省き、同一バッチ内のSBギフトは3件まで並列処理する。失敗分は0.6秒・1.6秒の間隔を置き1件ずつ再試行する（初回を含め最大3回）。詳細解析の画像取得は維持する。要確認の理由を判定画面に表示する。

利用者報告の「134件中成功60件・要確認74件」は未解決。本文で提示された1URLは正常解析・画像作成を確認できるが、要確認74件の対象URLは未取得のため、同じ原因と断定しない。撮影の既存上限は100件で、変更していない。

今回検証：3リポジトリ合計91テスト成功、両Workerのdry-runビルド成功。134件の撮影入力は100件で黙って打ち切らず、件数を表示して分割を案内する。公開・実ブラウザ確認は別工程。

## 2026-11-09 自動再試行5回

利用者指示により、両画面の撮影取得と共通APIのURL解析は、初回失敗後に最大5回再試行（初回を含め最大6回）する。撮影許可もURLごとに6回へ合わせた。成功したURLは再処理せず、既存の形式不正・未対応URL拒否、同時処理数、SBギフトの直列再試行を維持する。ローカルPNG変換と画面からAPIへの通信失敗に新しい自動再試行処理は追加していない。過去節の最大3回は履歴。
